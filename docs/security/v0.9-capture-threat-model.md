# Universal Capture Threat Model

## Scope

This threat model covers the v0.9 Universal Capture release: vendor adapters,
hook ingress, the private filesystem spool, normalization daemon, SQLite capture
journal and projections, retention and deletion, MCP tools, loopback dashboard,
exports, and context-compiler consumption.

Capture is an observational continuity subsystem. It is not an execution engine,
credential store, sandbox, model router, or authority source.

## Security Objectives

1. Capture only explicitly enrolled projects, sources, events, and fields.
2. Remove unknown fields and redact recognized secrets before durable queuing.
3. Route every event to the exact canonical project root and active policy.
4. Bound input size, nesting, item count, queue growth, replay, and exports.
5. Preserve append-only event identity and expose gaps, duplicates, and damage.
6. Keep mutable continuity content removable without rewriting integrity metadata.
7. Require separate, short-lived preview authorization for destructive actions.
8. Keep read, routine write, and destructive MCP capabilities distinct.
9. Never execute captured commands, prompts, tool output, or retrieved content.
10. Never promote captured observations to temporal truth implicitly.

## Protected Assets

- prompt, decision, approval, tool, command, file, and session continuity content;
- canonical project identity and source bindings;
- capture policies, enrollment state, cursors, and exclusion rules;
- event order, hashes, causal links, gaps, and provenance;
- forensic payload keys and explicitly retained forensic payloads;
- dashboard capability tokens and daemon launch locks;
- deletion, retention, adapter-installation, and governance receipts;
- brain database, private spool, control files, logs, exports, and backups.

## Actors And Assumptions

### Trusted

- the local operator controlling the selected OS account;
- the installed Rta-Smriti package and its verified release artifacts;
- an explicitly selected local adapter executable or language integration;
- an MCP host only within the capabilities granted at process launch.

### Untrusted

- every captured prompt, command, tool result, model response, repository file,
  browser excerpt, vendor field, and retrieved memory;
- malformed, oversized, duplicated, reordered, delayed, or adversarial hook input;
- repository-controlled configuration and paths;
- another local OS account without permission to the operator's private files;
- loopback HTTP requests without the current dashboard capability token;
- stale installation plans, receipts, cursors, and external session identifiers.

### Outside The Confidentiality Boundary

Administrator/root compromise, same-user malware, a compromised Python runtime,
and an attacker who can directly rewrite both the SQLite database and this
process's code can defeat local confidentiality. The controls still aim to make
accidental exposure, cross-project routing, corruption, and unauthorized use by
other local accounts fail closed.

## Trust Boundaries

1. **Vendor process to hook:** arbitrary vendor JSON crosses into an untrusted,
   bounded parser.
2. **Hook to private spool:** only normalized allowlisted fields may cross this
   durability boundary; raw vendor envelopes must not be written first.
3. **Spool to daemon:** atomic private records are claimed, revalidated, and
   either journaled, retried, or quarantined with bounded receipts.
4. **Daemon to SQLite:** canonical binding, active source, immutable policy,
   idempotency, sequence, and hash-chain checks precede append.
5. **Journal to mutable content:** immutable event identity is separate from
   removable normalized content and optional encrypted forensic payloads.
6. **SQLite to context compiler:** capture remains low-authority, bounded,
   checkpoint-fenced, privacy-filtered evidence.
7. **Local client to dashboard:** loopback address, Host/Origin checks, a
   high-entropy launch token, request limits, and bounded bodies protect APIs.
8. **MCP host to mutation tools:** read, routine capture writes, and destructive
   controls are separate launch-time capabilities. The multi-project gateway is
   project-scoped and read-only; mutation requires a single-project binding.
9. **Brain to export:** privacy ceiling, redaction verification, tombstones, and
   bounded stable writes apply before data leaves the brain.

## Primary Attack Paths And Controls

| Attack path | Required control | Failure behavior |
| --- | --- | --- |
| Secret or unknown vendor field reaches disk | Normalize, allowlist, and redact in memory before spool publication | Reject or return a bounded unavailable receipt |
| Provider credential appears in an ordinary free-text message | Detect provider-specific token formats independently of field names before spool, journal, replay, and export | Redact the credential; fail final privacy verification if residue remains |
| Oversized/deep JSON exhausts hook or daemon | 1 MiB ingress cap, event policy cap, depth/item budgets, bounded reads | Reject without partial authoritative append |
| Duplicate delivery creates duplicate history | Source-bound idempotency key and normalized digest | Return idempotent receipt; conflicting duplicate fails closed |
| Event is routed to another clone/project | Exact canonical root and registered source/policy binding | Reject before spool or journal mutation |
| Queue fills disk indefinitely | Per-source/global byte and record budgets, backpressure, bounded quarantine | Fail closed with an observable receipt |
| Partial write or daemon crash loses ordering | Same-directory atomic replace, fsync, processing recovery, append transaction | Recover/retry without silent promotion |
| Symlink, junction, reparse point, or replaced ancestor redirects adapter config | Preview-bound ancestor identities plus pre/post mutation revalidation | Refuse install/remove and preserve replacement target |
| Another local account reads control state | Owner-private POSIX modes or verified Windows DACLs on directories/files | Refuse lifecycle operation if privacy cannot be enforced |
| MCP read grant performs retention or deletion | Interactive retention, redaction, and deletion require an independent destructive capability plus preview-bound confirmation | Tool is absent and calls return not enabled |
| Stale UI preview deletes changed scope | HMAC confirmation token binds project, scope, actor, policy, counts, and expiry | Missing, forged, expired, or mismatched token is rejected |
| Deleted content returns through replay/export | Mutable event content and payload rows are tombstoned and filtered; replay reads content and tombstones from one database snapshot | Return metadata-only deleted state |
| Routine MCP write removes a source | MCP source-state dispatch accepts only active or paused; irreversible removal stays outside routine agent grants | Reject the state transition |
| Diagnostics exhaust a mature journal | Default diagnostics verify a fixed-size prefix and disclose whether verification is complete | Return bounded partial verification metadata |
| Root-level absolute path escapes redaction | Windows drive-root and POSIX root-level paths are detected before durable capture and agent reads | Redact and fail final privacy verification if residue remains |
| Project-bound status reveals another project's activity | Queue occupancy is derived only from the selected project's source tokens and database-wide daemon counters are omitted | Return project-scoped counts and lifecycle state only |
| Project-scoped lifecycle status infers foreign Codex session activity | Keep global binding diagnostics out of the public MCP lifecycle projection | Return no recent, foreign, or invalid session aggregates to project-bound readers |
| Stale enrollment restarts capture against a reused old root | Compare the private receipt root with the brain's current canonical project binding before starting any service | Mark that enrollment error and start none of its workers |
| Default MCP lifecycle reads reveal host paths or control metadata | Apply a strict path-free public projection and expose only bounded counters plus `has_error` | Omit database/root/session paths, PID identity, launch material, and raw errors |
| Reused PID is mistaken for a managed continuity worker | Bind lifecycle state to PID plus cross-platform process-birth identity | Recover only after a confirmed mismatch; a live but unverifiable identity fails closed without clearing, signaling, or duplicating the process |
| Memory-write grant controls a background worker | Keep continuity process control in an independent launch-time MCP capability | Tool remains absent unless the operator explicitly grants process control |
| Privacy filtering hides a corrupted journal link | Verify every scanned chain link and its normalized content before privacy projection | Reject the page instead of skipping hidden corruption |
| Paginated export or replay trusts a corrupted cursor anchor | Verify the anchor event and predecessor link before resuming the page | Reject the page and do not claim bounded journal verification |
| Redacted export emits tampered mutable content | Recompute content, normalized-event, envelope, sequence, and chain hashes before redaction | Reject the export even if the attacker updated the mutable content digest |
| Captured prompt injects agent instructions | Treat all capture and retrieval text as untrusted data | Display/retrieve only; never execute |
| Corrupt journal hides damage | Deterministic event chain, sequence checks, integrity verification | Report invalid chain/gap; do not claim continuity readiness |
| Capture claims become project truth | No automatic capture-to-truth transition exists | Explicit future promotion must bind event hashes and authority |

## Integrity Semantics

The event chain is an unkeyed deterministic hash chain. It detects accidental
damage and unsophisticated tampering. It does **not** authenticate the database
against an attacker who can rewrite rows and recompute every later hash. Signed
snapshots can authenticate a chosen snapshot, but do not make a live compromised
database trustworthy.

Normalized content is stored separately from immutable event identity. When
content is present, its digest and normalized event digest are checked. After
retention or deletion removes content, the immutable envelope and event chain
remain verifiable, but removed content cannot be recomputed.

## Deletion And Retention Semantics

- Preview is non-mutating and returns a five-minute, process-local confirmation
  token bound to the exact affected counts and policy.
- Interactive retention binds its policy, cutoff, run, batch size, state fence,
  affected counts, and operator. The background daemon may enforce only an
  already-authorized immutable retention policy without an interactive prompt.
- Confirmation removes normalized content and forensic payload bytes from the
  current database and writes an immutable tombstone receipt.
- Optional secure SQLite compaction is best effort. It is not a claim of physical
  media erasure.
- Deletion does not erase prior backups, exported bundles, filesystem snapshots,
  cloud/device copies, swap, journal remnants already copied elsewhere, or data
  retained by an external source. Those copies require their own lifecycle.
- A process restart invalidates outstanding confirmation tokens by design.

## Promotion Boundary

The v0.9 capture candidate implements no automatic path from observations to
accepted temporal truth. A future promotion mechanism must require a deterministic
rule or explicit operator action, bind the exact source event hashes, preserve
authority and uncertainty, and retain provenance when source content is later
deleted. Model output alone must never authorize promotion.

## Privacy Defaults

- Capture enrollment is opt-in and reversible.
- Unknown event types and fields are dropped unless policy explicitly enables
  vendor-event metadata.
- Identifiers are validated or converted to opaque digests.
- Raw headers, environment maps, cookies, tokens, clipboard data, credentials,
  and unrelated browser content are excluded.
- Forensic payload retention requires a separate grant and local key.
- Diagnostics and receipts expose bounded counts and digests, not private paths,
  payloads, keys, or source text.
- Support exports are bounded, redacted, and never include forensic payloads.

## Required Validation Evidence

Release qualification must verify:

- pre-spool secret/unknown-field absence by inspecting durable spool bytes;
- duplicate, gap, late-event, crash, queue-full, disk-full, and database-lock paths;
- 10,000-event replay in at most 2 seconds and 200 MiB peak Python allocation;
- daemon idle CPU/memory and multi-hour bounded soak behavior;
- Windows DACL, POSIX mode/owner, symlink, hardlink, junction, and ancestor-swap tests;
- missing, forged, expired, mismatched, and replayed deletion confirmations;
- default-read, routine-write, and destructive MCP capability matrices;
- loopback dashboard authentication, body/concurrency limits, browser errors,
  keyboard access, responsive layouts, and human-operator journeys;
- migration, clean install, installed wheel, frozen binary, upgrade, rollback,
  uninstall, and restart on Windows, macOS, and Linux;
- Gitleaks, actionlint, dependency audit, SBOM, Ruff, compileall, package-content,
  privacy, security-diff, and repository test results with unavailable tools
  reported honestly.

## Residual Risks

- Same-user malware or administrator/root access can read operator-owned files.
- A directly writable database plus compromised runtime can defeat the unkeyed
  chain unless a separately authenticated snapshot is available.
- Secret detection is defense in depth, not proof that arbitrary unknown secret
  formats can never appear in operator-approved content fields.
- Vendor hook formats can change; unsupported fields/events are dropped until an
  adapter update is reviewed and tested.
- Filesystem APIs cannot promise erasure from SSD wear leveling or external copies.
- Optional external adapters and local models inherit their own supply-chain and
  execution risks and remain disabled unless explicitly configured.

## Incident Response

Pause the affected source, preserve a private diagnostic receipt, verify canonical
binding and journal integrity, rotate exposed local keys/tokens, remove compromised
adapter configuration through its receipt, and restore from a verified snapshot
only after identifying the last trustworthy boundary. Never publish a brain,
spool, transcript, key, raw diagnostic bundle, or private path as an issue sample.
